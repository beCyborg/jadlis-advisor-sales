# Deal Profile Gate — интейк типа сделки (Phase A)

Цель: собрать `DEAL_PROFILE` за ≤2 экрана AskUserQuestion и вычислить из него
(а) жёсткие гейты — кто из советников выпадает, (б) `FitMultiplier` — множитель веса
валидатора на советника. Профиль печатается в шапке вердикта; FitMultiplier — отдельной
колонкой карты консенсуса.

## Экран 1 (все режимы)

Четыре вопроса одним AskUserQuestion:

1. **Тип сделки** (motion/market): исходящая B2B / входящая-inbound / founder-led свой
   продукт / услуги-консалтинг / транзакционная-массовая.
2. **ACV** (порядок чека): micro <$5K / low $5–25K / mid $25–100K / high >$100K.
3. **Стейкхолдеры**: один ЛПР / 2–3 / комитет 4+.
4. **Что продаём**: продукт-SaaS / услуга / консалтинг / инфопродукт.

Если профиль уже есть в памяти `{MEMORY_DIR}/Профили/adv-sales.md` (секция Profile) и запрос
ему не противоречит — экран 1 пропустить, взять из памяти, сказав об этом вслух.

## Экран 2 (только DEAL)

1. **Где застряло**: после дискавери / после демо-КП / на переговорах о цене / «тишина» /
   постоянно откладывают решение.
2. **Сколько висит**: <2 недель / 2–6 недель / >6 недель.
3. **Кто в решении со стороны клиента и кто чемпион** (свободный ответ).
4. **Против кого/чего играем**: конкурент / статус-кво «ничего не делать» / внутренняя
   разработка / неизвестно.

**Ответ «не знаю» на экране 2 — не допущение, а сам по себе диагноз** (провал дискавери
или отсутствие чемпиона) — фиксируется как находка и попадает в вердикт.

## Жёсткие гейты (советник исключается из прогона)

| Условие профиля | Выпадает | Причина |
|---|---|---|
| ACV micro/low **и** стейкхолдеров <3 | qsl | MEDDPICC окупается с ~$25K и 3+ стейкхолдеров; иначе удлиняет цикл |
| Один ЛПР | selling-with | вся книга про комитет и чемпиона |
| ACV micro (<$5K) | weiss, negotiation | value-based fees и переговорный фундамент не окупаются на микрочеке |
| Транзакционная-массовая продажа | gap, khalsa, enns | консультативное дискавери = допрос; позиция эксперта нерелевантна |
| Не услуги/консалтинг | weiss | цена от ценности — консалтинговый инструмент |

## FitMultiplier (мягкая поправка веса, ×0.4–×1.2)

| Профиль | Советник | × | Почему |
|---|---|---|---|
| услуги/консалтинг | khalsa, enns, weiss | 1.2 | родной контекст |
| founder-led | founding | 1.2 | родной контекст |
| комитет 4+ | selling-with, qsl | 1.2 | родной контекст |
| inbound | gap | 0.7 | discovery-fatigue риск |
| любой | voss (стратегические claims) | 0.4 | микрослой, не система |
| не investor/high-stakes | klaff-frame | 0.5 | метод из capital-raising |
| транзакционная | spin, jolt | 0.7 | консультативная база |
| ACV high + комитет | dunford-pitch, resonate | 1.1 | питч-слой релевантнее |

Непокрытые комбинации = ×1.0. Валидатор печатает применённые множители в карте консенсуса.

## Выход

```
DEAL_PROFILE = {motion, acv, stakeholders, offer, market, stuck?, age?, committee?, against?}
EXCLUDED = [советники по жёстким гейтам, с причинами]
FIT = {советник: множитель}
```

Субсеттинг ростера режима (routing-matrix) применяется ПОСЛЕ гейтов; N_built считается
после субсеттинга по preflight `ls -d`; quorum = max(3, ceil(0.75 × N_built));
N_built < 4 → совет не созывается, предложить standalone-советника.
