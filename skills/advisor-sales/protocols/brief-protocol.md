# Brief Protocol — контракт брифа WRITE (adv-sales)

Интервью в главной сессии (≤2 экрана AskUserQuestion + свободные ответы), результат —
объект `brief` строго по контракту `sales-write-pipeline.js`:

```
brief = {
  task:        что пишем, одной фразой,
  type:        'outreach' | 'followup' | 'proposal' | 'call-script' | 'pitch-deck',
  language:    'ru' | 'en',
  dealProfile: {motion, acv, stakeholders, offer, market},   // из deal-profile-gate
  audience:    кто читает: роль, что у него болит, ДОСЛОВНЫЕ фразы клиента,
  offer:       что предлагаем + реальные пруфы (кейсы, цифры — только настоящие),
  context:     история касаний: что уже было (звонки, письма, демо), что клиент знает,
  objective:   что должно произойти после прочтения/звонка (конкретное действие),
  constraints: лимиты (длина, тон, каналы, что нельзя говорить),
  swipeFile:   '{MEMORY_DIR}/Продажи/_Свайп-файл.md'  // может не существовать
}
```

## Правила интервью

- **Язык текста** (`language`) — по брифу, не по языку сессии.
- **Реальный язык клиента**: просить дословные фразы из переписки/звонков — как клиент
  сам называет проблему. Выдуманные формулировки помечать как гипотезу в `context`.
- **Пруфы только реальные**: кейсы/цифры в `offer` из брифа, не сочиняются.
- **История касаний обязательна**: sales-текст без контекста «что было до» — главный
  источник фальшивых писем. Нет истории (холодный первый контакт) — так и записать.
- **DEAL_PROFILE обязателен** (экран 1 гейта или память): критики применяют Deal-gate
  ходов против него.
- Тип неочевиден → AskUserQuestion; вебинар/сцена → отказ (контур отложен).
