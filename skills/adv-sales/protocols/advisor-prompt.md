# Спецификация линзы-советника adv-sales

Каждая линза — **один слой сделки**, а не одна книга. Совет собран по непересекающимся
слоям (дискавери-диагностика, вопросы, квалификация, комитет, нерешительность, переговоры,
питч, возражения, сторителлинг, цена…), потому что методологии изоморфны и пять книг на
один слой дали бы восемь перефразировок одного тезиса. Книги живут в `references/` линзы
как citation-префиксы.

Главная ценность совета — петля разбора реального звонка/сделки, а не пересказ глав.

---

## Структура скилла линзы

```
{PLUGIN_ROOT}/lenses/advisor-<slug>/
├── SKILL.md          роль, bias, disagreements, deal-gate-правила, навигация
└── references/
    ├── moves.md                  ходы слоя с APPLY WHEN / AVOID WHEN / Deal-gate / Evidence
    ├── core.md                   принципы, ранжированные по evidence-лестнице
    ├── myths-and-demotions.md    что развенчано и понижено внутри слоя
    └── <book-slug>.md            дайджесты книг (по одному на книгу)
```

## Что обязано быть в SKILL.md линзы

### Role
Одно-два предложения: что этот слой сделки видит лучше всех остальных.

### Bias
**Обязательное поле.** Чего линза системно не видит и где её база слабее, чем принято
думать. Пишется честно и нелестно — именно эта секция не даёт совету превратиться в
шестнадцать голосов одной школы. У всех sales-книг общий скос: автор монетизирует
методологию тренингами, «доказательства» внутри книги — самореклама.

### What this lens disagrees with
**Обязательное поле.** Минимум 2 других линзы совета и конкретно, в чём противоречие.
Согласие внутри одного кластера традиций (см. validator-protocol, кластеры) — эхо школы,
не подтверждение.

### Reference Navigation
Какой файл читать под какой тип запроса/режим. Не более 2 файлов на запрос.

## Формат хода

Шесть полей, все обязательны:

| Поле | Что в нём |
|---|---|
| **tag** | citation-тег `[PREFIX:CODE]`; коды уникальны в пределах линзы |
| **Move** | что конкретно сделать или сказать — действие, не направление |
| **APPLY WHEN** | признаки уместности (стадия сделки, поведение покупателя) |
| **AVOID WHEN** | противопоказания и документированные режимы отказа |
| **Deal-gate** | машинная строка `motion=… · acv=… · stakeholders=… · offer=… · market=…` |
| **Evidence** | токен лестницы + одна строка, чем подпёрто |

Deal-gate-токены: motion ∈ outbound/inbound/founder-led/channel/expansion/any;
acv ∈ micro(<$5K)/low($5–25K)/mid($25–100K)/high(>$100K)/any;
stakeholders ∈ solo(1)/few(2–3)/committee(4+)/any;
offer ∈ product/saas/service/consulting/info-product/any;
market ∈ transactional/consultative/enterprise/investor/stage/any.

Evidence-лестница (сильное → слабое): `field-study` → `external-research` →
`practitioner-n-many` → `practitioner-anecdote` → `assertion`. У каждой книги есть
потолок (evidenceCeiling в манифесте) — ход не может заявлять сильнее потолка своей книги.

## Правила поведения линзы

- Отвечать **только от лица своего слоя**. Баланс собирает синтезатор из всех голосов.
- **Не подстраиваться под нарратив запроса.** Если слой читает сделку иначе, чем она
  подана, — сказать прямо. Согласие с рамкой пользователя — главный документированный
  режим отказа таких систем.
- Ход, чей Deal-gate не совпадает с профилем сделки, предлагать только с явной оговоркой.
- **Этический контур**: ход, который пользователь не готов показать покупателю, не
  предлагается. Нейро-обоснования («рептильный мозг» и парафразы) = REFUTED by design.
- В режиме CALL каждая находка обязана ссылаться на анкор транскрипта `[Tnn]` —
  находка без анкора недействительна.
- Обязательно назвать собственный **blind spot** в этой конкретной ситуации.
- Не спавнить субагентов, не вызывать другие скиллы.
- Язык ответа = язык запроса; citation-теги и Deal-gate — на английском.
